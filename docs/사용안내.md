# 고구맙습니다 운영 안내

## 관리자 화면

판매 페이지 하단의 **농부 관리실** 또는 `/admin.html`로 들어갑니다. 등록한 관리자 이메일과 직접 설정한 비밀번호로 로그인합니다. Supabase 대시보드 계정과 이 홈페이지의 관리자 계정은 별개입니다.

처음 사용하는 관리자라면 이메일과 새 비밀번호(12자 이상)를 입력하고 **처음 비밀번호 설정**을 누릅니다. 확인 메일의 링크로 이메일을 인증한 뒤 로그인합니다. 인증 화면이 다른 주소로 열려도 인증이 완료되었다면 관리자 페이지로 돌아와 로그인할 수 있습니다.

로그인 상태는 같은 브라우저·사이트 주소에서 로그인한 날부터 **14일** 동안 유지됩니다. 새로고침하거나 브라우저를 닫았다 열어도 자동 복원하며, 짧은 인증 유효기간은 자동으로 갱신합니다. 이번 변경 이후 한 번 로그인하면 적용됩니다. 로그아웃하면 같은 사이트의 다른 탭에서도 종료되며 저장된 인증 정보가 삭제됩니다. 비밀번호와 주문 정보는 저장하지 않습니다.

연결이 잠시 끊기면 로그인 정보를 지우지 않고 **로그인 상태 다시 확인**을 표시합니다. 비밀번호 변경·서버의 세션 취소, 14일 경과, 브라우저 데이터 삭제 시에는 다시 로그인합니다. 시크릿 모드나 저장 차단 설정에서는 유지되지 않을 수 있습니다. 공용 기기에서는 사용 후 로그아웃하세요.

## 하루의 주문 처리

1. **새로고침**을 눌러 최신 주문과 재고를 확인합니다.
2. 상단의 **입금 대기** 건수를 눌러 주문을 모아 봅니다. 은행 내역에서 입금자와 금액을 확인한 주문들을 체크합니다. 표 맨 위 체크박스는 현재 페이지의 변경 가능한 주문을 모두 선택합니다.
3. 목록 위의 **선택 주문 상태 변경**을 눌러 **입금 확인(배송 준비)**으로 변경합니다. 상품 중량 × 수량만큼 판매 가능 재고에서 차감합니다.
4. **입금 확인(배송 준비)** 목록에서 발송할 주문들을 체크합니다. 공통 택배사 또는 배송 방법과 주문별 송장번호(선택)를 입력하고 **배송 중**으로 변경합니다.
5. **배송 중** 목록에서 실제 배송이 완료된 주문들을 체크한 뒤 **배송 완료**로 변경합니다. 완료 시각이 저장됩니다.

같은 단계의 주문을 현재 페이지에서 최대 50건까지 함께 처리할 수 있습니다. 검색·단계·페이지를 바꾸거나 새로고침하면 선택이 해제됩니다. 주문번호를 누르면 배송지·메모 확인과 개별 상태 변경·취소도 가능합니다. 배송 완료·취소 주문은 일괄 선택에서 제외합니다.

재고 부족이나 다른 화면의 변경으로 처리할 수 없는 주문이 있으면 선택한 주문 전체가 저장되지 않습니다. 연결이 끊겨 결과를 확인하지 못한 경우에는 **처리 결과 다시 확인**을 누르세요. 같은 요청을 확인하므로 재고가 중복 차감되지 않습니다.

배송 전에는 취소할 수 있습니다. 확정된 주문을 취소하면 재고가 복구되고, 접수 상태에서 취소하면 재고는 바뀌지 않습니다. 발송 후 취소·반품은 자동 처리하지 않습니다.

접수는 재고 예약이 아닙니다. 여러 주문이 동시에 들어와도 확정 시 남은 재고를 확인하므로 마이너스 재고가 생기지 않습니다. 동시 편집으로 정보가 바뀌면 새로고침하도록 안내합니다.

## 재고

**재고 입고 · 조정**에서 입고/차감, kg, 변경 사유를 입력합니다. 소수 셋째 자리(1g)까지 기록할 수 있습니다. 관리자 화면에는 현재 판매 가능 kg와 최근 30건의 변경 이력이 표시됩니다. 주문에 따른 차감과 취소 복구도 이력에 남습니다.

## 비용 없이 보내는 선물

관리실 상단의 **선물 주문 등록**을 누릅니다. 상품(기본 5kg)과 수량, 받는 분의 이름·연락처·우편번호·주소를 입력합니다. 주소 검색 또는 직접 입력을 사용할 수 있으며 연락처에는 하이픈이 자동으로 붙습니다. **받는 분 추가하기**로 한 번에 최대 20곳을 등록할 수 있습니다.

등록 시 총 중량을 확인하고 저장하면 바로 재고를 차감하고 **배송 준비** 상태가 됩니다. 입금을 받을 필요가 없는 주문이며 상품과 배송비의 청구액은 모두 0원입니다. 실제 택배비 지출을 기록하는 기능은 별도입니다. 목록에서 **선물 · 무상** 표시를 확인하거나 **주문 구분 → 선물 주문**으로 모아볼 수 있습니다. 상단 단계별 건수는 일반·선물을 합친 전체 주문 기준입니다.

이후에는 기존과 같이 주문을 체크해 배송 중·배송 완료로 변경합니다. 배송 전 취소하면 차감한 재고가 복구됩니다. 여러 곳 중 입력 오류나 재고 부족이 있으면 전체 등록이 취소됩니다. 결과를 확인하지 못했을 때는 같은 화면에서 **등록 결과 다시 확인**을 누릅니다. 선물 내역은 관리자 화면에서만 관리하며 고객 주문 조회에는 포함하지 않습니다.

## 고객 주문서

주문자 이름·연락처는 한 번만 입력합니다. 받는 분마다 상품·수량·성함·연락처·우편번호·주소·배송 메모를 작성하고, **받는 분 추가하기**로 최대 20곳까지 추가할 수 있습니다. 기본 상품은 각 배송지 모두 5kg입니다. **주문자와 같아요**는 입력한 주문자 이름과 연락처를 복사합니다.

**주소 검색**으로 [카카오 우편번호 서비스](https://postcode.map.kakao.com/guide)를 열면 우편번호와 기본 주소가 자동 입력됩니다. 상세 주소만 이어서 입력하세요. 검색 서비스 연결이 어려우면 **주소 검색이 어려우면 직접 입력**으로 우편번호와 주소를 적을 수 있습니다. 주소 검색은 버튼을 누를 때만 외부 서비스를 불러옵니다. 주문자와 받는 분 연락처는 숫자를 입력하면 하이픈이 붙습니다.

개인정보 수집·이용 체크는 기본 선택 상태이며, 해제하면 접수할 수 없습니다. **주문하기** 버튼 바로 위의 할인코드 칸에 코드를 적용합니다. 금액을 확인하고 **주문하기**를 누르면 접수합니다. 실제 저장이 확인된 뒤에만 배송지별 주문 카드와 입금 안내를 표시합니다. 접수 후 **새 주문하기**를 누르면 같은 주문자가 추가 주문을 작성할 수 있습니다.

**주문서 확인하기**는 이미 접수한 주문의 조회 화면입니다. 주문할 때 입력한 **주문자 성함과 연락처**를 입력하면 해당 정보와 일치하는 모든 주문을 최신순으로 보여 줍니다. 20건을 넘으면 **이전 주문 더 보기**를 누릅니다. 카드에서 상품, 수량, 할인·배송비·금액, 입금 대기·입금 확인(배송 준비)·배송 중·배송 완료·취소 상태를 확인합니다. 받는 분 성함은 일부 가리고 연락처와 주소는 표시하지 않습니다. 관리자 상태 변경은 다시 조회하면 반영됩니다. 접수 직후에는 **주문서 확인하기** 버튼이 성함과 연락처를 자동 입력합니다.

이름·연락처 조회는 문자 인증 방식이 아닙니다. 전체 주소나 연락처 등 상세 개인정보는 관리자 화면에서만 확인합니다. 같은 연락처로 15분 내 20회를 초과해 조회하면 잠시 제한합니다. 입력 정보와 내역은 브라우저 저장소에 보관하지 않습니다.

여러 배송지는 함께 저장되며 하나라도 입력 오류가 있으면 전체 접수가 중단됩니다. 관리실에서는 배송지별 주문으로 표시되므로 개별로 처리하거나 같은 단계의 주문을 선택해 일괄 처리할 수 있습니다. 주문 상세의 주문 묶음 번호로 같은 접수에 속한 배송지를 확인할 수 있습니다. 기존 주문에는 우편번호가 없을 수 있습니다.

주문서 왼쪽에 카카오톡 주문 안내 문구를 넣었습니다. 채널이나 오픈채팅 링크는 연결하지 않았습니다.

연결이 끊겨 결과를 알 수 없는 경우에는 입력을 고정한 채 같은 주문을 다시 확인하도록 합니다. 같은 화면에서 재시도하면 주문이 중복 생성되지 않습니다. 이때 새로고침하거나 새 주문서를 만들지 말고 기존 버튼으로 재시도하세요.

접수 후에는 **입금까지 완료해야 주문이 완료됩니다**라는 안내와 입금액, 설정한 은행·계좌·예금주가 표시됩니다. 관리자 화면의 **입금 대기**는 접수 상태입니다. 은행 내역을 직접 확인한 뒤 **입금 확인(배송 준비)**을 누르세요. 사이트는 입금을 자동 확인하지 않습니다. 주문 알림, 택배 추적도 자동 처리되지 않습니다. 수집한 고객 정보의 보관·파기 기준과 운영 연락처는 판매자가 운영 정책에 맞게 정해야 합니다.

## 상품과 할인

| 항목 | 내용 |
| --- | --- |
| 품종 / 크기 | 호풍미 / 혼합 |
| 가격 | 2kg 10,000원 / 5kg 20,000원 |
| 배송비 | 배송지 한 곳당 3,500원 |
| 할인코드 | GOGUMA · 상품 금액의 10% (배송비 제외) |

예: 5kg 1개에 할인 적용 시 20,000 − 2,000 + 3,500 = 21,500원입니다. 2kg 한 개는 1,000원, 5kg 한 개는 2,000원 할인되며 수량에 따라 할인액이 늘어납니다. 두 곳에 5kg 1개씩 보낼 때는 40,000 + 7,000 − 4,000 = 43,000원입니다. 기간과 고객별 횟수 제한은 없습니다.

할인액은 각 배송지의 상품 금액에 따라 기록합니다. 기존 접수 주문의 금액은 바꾸지 않습니다. 결제 및 환불 금액은 판매자가 확인해 안내합니다.

가격과 판매 여부는 Supabase `farmer_products`에서 수정합니다. 할인코드는 비공개 `farmer_private.discount_codes`의 `code`, `percent`, `amount`, `active`로 관리합니다. `GOGUMA`의 `percent`는 10, `amount`는 0입니다. `percent`가 0이면 기존 고정 금액 할인 방식이 사용됩니다. 화면의 계산은 서버 값을 사용하고 접수 때 다시 검증합니다. 상품명이 바뀌면 HTML의 기본 표시와 메타 설명도 함께 수정하세요. 배송비 정책 변경은 데이터베이스 함수와 화면 기본값을 함께 수정해야 합니다.

## 디자인 편집

브랜드 이야기와 Q&A는 `index.html`의 본문, 색상은 `:root`의 색상 변수를 편집합니다. 캐릭터와 스타일은 HTML에 내장되어 있습니다. 상품·주문 동작은 `customer.js`, 관리자 동작은 `admin.js`와 `admin-gifts.js`입니다. 배포 시 README의 실행 파일과 `payment-config.js`를 같은 폴더에 두세요. 입금 계좌는 `payment-config.js`의 `bank`, `account`, `holder`를 편집합니다. 이 파일은 공개 GitHub 저장소에 포함하지 않습니다.
