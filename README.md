# 어쩌다 농부 · 고구맙습니다

태안에서 어쩌다 농부가 된 부부의 이야기와 첫 고구마를 소개하는 한국어 원페이지 웹사이트입니다. Supabase에 주문을 저장하고 관리자 화면에서 재고와 배송을 관리합니다.

[판매 페이지](https://eojjeoda-farmer-gogumap.silver-lynx-2417.chatgpt.site/) · [농장 관리](https://eojjeoda-farmer-gogumap.silver-lynx-2417.chatgpt.site/admin.html)

## 실행

설치·빌드 없이 정적 서버에서 실행합니다. 이미지와 스타일은 HTML에 내장되어 있으며, 온라인 주문·로그인은 인터넷 연결이 필요합니다.

```sh
python3 -m http.server 8000
```

`http://localhost:8000`을 여세요. 배포할 때는 아래 실행 파일들과 `payment-config.js`를 같은 폴더에 함께 올립니다.

- `index.html`: 브랜드 이야기, 상품, 주문서
- `admin-discounts.js` / `admin-discounts.css`: 비공개 할인 코드 등록·수정·삭제, 활성화, 수량·사용 내역
- `admin-simulator.js` / `admin-simulator.css` / `simulation-math.js`: 장부·재고 연동 가격 시뮬레이션
- `customer.js`: 상품 조회·할인 확인·주문 접수·기존 주문 조회
- `admin.html`, `admin.js`, `admin-gifts.js`: 관리자 로그인, 일반·선물 주문과 배송·재고 관리
- `admin-finance.js`, `admin-finance.css`: 관리자 전용 손익분석과 수입·지출 장부
- `farmer-api.js`: Supabase 통신과 관리자 세션
- `farmer-config.js`: 프로젝트 URL과 공개 publishable key
- `payment-config.js`: 고객에게 안내하는 입금용 은행·계좌·예금주 설정입니다. 주문 접수 후 입금 안내에 표시되며 배포 누락을 막기 위해 저장소에 포함합니다. `payment-config.example.js`는 다른 계좌로 설정할 때 참고하는 빈 예시입니다.

## 주문과 재고

- 호풍미 2kg 12,000원 / 5kg 22,000원, 기본 선택 5kg. 특·대·소·한입 사이즈의 혼합 구성입니다.
- 받는 분과 배송지를 최대 20곳까지 추가할 수 있습니다. 배송지마다 상품·수량을 선택합니다.
- 모든 배송지 무료배송, `GOGUMA`는 상품 금액의 10% 할인
- 주소 검색으로 우편번호·주소를 자동 입력하고, 연락처에는 하이픈을 자동으로 붙입니다.
- 가격·할인·수량은 서버에서 검증합니다.
- 입금 대기 → 입금 확인(배송 준비) → 배송 중 → 배송 완료. 입금 확인 시 중량 × 수량만큼 재고를 차감합니다.
- 관리자 상단의 단계별 건수를 누르면 해당 주문만 표시합니다. 같은 단계의 주문을 체크한 후 목록 위에서 다음 상태로 일괄 변경할 수 있습니다(현재 페이지 최대 50건). 필터·검색·페이지를 바꾸면 선택이 초기화됩니다.
- 배송 중으로 변경할 때 공통 택배사/배송 방법과 주문별 송장번호(선택)를 입력합니다. 배송 완료·취소된 주문은 일괄 선택에서 제외하며, 개별 취소는 주문 상세에서 처리합니다.
- 일괄 변경은 하나의 거래로 저장합니다. 재고 부족·오래된 주문 정보·잘못된 전환이 있으면 전체를 되돌립니다. 응답 유실 시 같은 요청으로 다시 확인하므로 재고가 중복 차감되지 않습니다.
- 배송 전 취소 시 확정 때 차감한 재고를 복구합니다. 접수만 된 주문은 재고를 차감하지 않습니다.
- 재고 입고·조정과 변경 사유, 발송 정보, 배송 완료 일시를 기록합니다.
- **선물 주문 등록**은 관리자만 사용할 수 있습니다. 받는 분을 최대 20곳까지 추가하고, 각 상품·수량·연락처·우편번호·주소를 입력합니다. 상품·배송비 청구액은 0원이며 등록과 동시에 재고를 차감하고 배송 준비로 저장합니다. 일반/선물 필터와 선물 표시로 구분하고 기존 일괄 배송 처리를 사용합니다. 배송 전 취소하면 재고가 복구됩니다.

주문 접수 후 설정한 입금 계좌와 총 입금액을 안내합니다. 입금까지 완료해야 주문이 완료되며, 관리자가 입금을 확인한 뒤 주문을 확정합니다. 자동 입금 확인, 택배사 자동 배송 추적, 문자·메일 알림은 연결하지 않았습니다.

**주문하기**에서 새 주문을 접수하고, **주문서 확인하기**에서 주문자 성함과 연락처로 기존 내역을 조회합니다. 상품·금액·입금/배송 상태를 카드로 표시하며, 받는 분 성함은 일부 가리고 연락처·주소는 반환하지 않습니다. 내역은 최신순 20건씩 표시합니다.

## 관리자와 개인정보

관리자는 Supabase Auth에서 이메일을 확인한 계정 중 비공개 허용 목록에 등록된 계정만 가능합니다. 비밀번호와 로그인 세션은 코드에 넣지 않습니다. 공개 키만으로 전체 주문 목록을 읽거나 재고를 변경할 수 없습니다.

공개 데이터베이스 테이블의 직접 접근은 모두 차단했습니다. 공개 RPC는 상품/금액 조회, 주문 접수, 이름·연락처가 일치하는 제한된 주문 조회를 허용하고, 관리자 RPC는 서버에서 이메일 인증과 허용 목록을 검사합니다. 고객 정보는 HTML이 아닌 일반 텍스트로 렌더링합니다.

### 고구마의 TMI

- `tmi.html`: 별도 공개 기록 페이지. 메인 메뉴, 소개와 상품 사이, 하단에서 연결합니다.
- `tmi.css`: TMI 전용 반응형 스타일.
- `tmi-data.js`: 연도, 원북면 참고 좌표, 고정 재배기간, 자재 사용 기록, 사람들 소개를 수정하는 설정 파일.
- `tmi.js`: 저장된 재배기간 날씨의 표시, 누락값 처리, 기온·강수량 그래프와 달력, 제품 분류, 사람들의 이야기를 차례로 표시하는 기능.

날씨는 확정된 재배기간 **2026-06-07~2026-10-15**(양끝 포함 131일)으로 고정되어 있습니다. 방문자가 기간을 변경하는 입력창은 없습니다. `tmi-weather-2026.js`에 NASA POWER 일별 자료와 원본 요청 URL·확보일을 저장해 페이지가 외부 API를 매번 호출하지 않고 바로 표시합니다. 대표 좌표는 원북면 원이로 인근(36.83, 126.27)으로, 농장의 정확한 좌표나 실측 기상자료가 아닙니다. 날짜는 LST 기준이며 누락값은 0으로 채우지 않습니다. 기간이나 좌표를 수정하려면 해당 데이터도 다시 확보해야 하며, 서로 맞지 않으면 수치를 표시하지 않습니다. 자료 출처: [NASA POWER](https://power.larc.nasa.gov/docs/acknowledgements/).

농부가 확인한 바에 따라 자재 7개 품목은 기록된 날짜에 **전체 수량을 실제 사용한 내역**으로 표시합니다. N·P·K 그래프는 제품명에 기록된 성분 표기의 비교이며 고구마의 실제 흡수량을 뜻하지 않습니다. LD흑유 비닐 3개는 영양분이 아닌 밭을 덮는 자재로 구분합니다. 공급자 이름, 비용, 고객 및 배송지 정보는 공개 페이지에 포함하지 않습니다. 4~7번 크기 도감·행선지·가희와 세환이의 회고록은 준비 중입니다.


### 사람들 도트 캐릭터 지도

`people-characters.js`는 외부 이미지 없이 원본 SVG 도트 캐릭터와 역할 소품을 그립니다. 실제 외모를 재현하지 않는 상징적 그림입니다. `people-map.js`와 `people-map.css`가 네 장면(방향 안내 → 밭 준비 → 함께한 재배 → 수확)을 모두 펼쳐 표시합니다. 소개와 이름·기관·역할은 `tmi-data.js`의 `people`에서 편집합니다. 같은 `id`와 `avatar`를 쓰는 사람은 다른 장면에서도 같은 캐릭터입니다. 기관 캐릭터와 이웃 캐릭터는 대표 그림이며 실제 인원 집계를 뜻하지 않습니다. 아이들 3명과 반도인력 4명은 제공된 수에 맞춰 각각 표현합니다. 부부는 03번 재배 장면에 통합했습니다.

메인·TMI·관리자 페이지의 상단 공통 메뉴는 `site-navigation.css`를 사용하며, 농부의 이야기·고구마의 TMI·선물하기·고구마 주문하기 네 항목으로 통일했습니다. 관리자 로그아웃은 본문의 관리 도구로 유지합니다.


### 호풍미 5kg 방문 수령

- 상품 `hopungmi-5kg-pickup`: **호풍미 5kg 방문 수령 / 18,000원**, 추가 배송비 없음. 기본 선택은 기존 택배 5kg 상품입니다.
- 수령 장소: **원북면 원이로 804-59 (홍세환 소셜라운지)**. 방문 일정은 주문 후 안내합니다.
- 방문 수령을 선택하면 배송 주소·우편번호를 요구하지 않습니다. 수령인 성함·연락처와 메모를 받으며, 배송 상품과 한 주문서에 함께 넣을 수 있습니다.
- 전용 상품 ID를 기준으로 서버가 수령 방식을 판단합니다. 수령 장소는 서버가 저장하므로 임의 배송지를 보내 방문 상품을 택배 상품으로 바꿀 수 없습니다. 기존 상품과 같은 재고를 사용하며, 입금 확인 시 5kg씩 차감합니다.
- 관리자 목록·조회·상세에서 방문 수령을 표시하고, `입금 대기 → 입금 확인(수령 준비) → 수령 대기 → 수령 완료`로 관리합니다. 수령 대기에서도 취소 시 재고를 복구합니다. 택배 상품에는 기존 배송 정보 검증을 유지합니다.
- `20261019012333_pickup_5kg_product.sql`은 새 상품과 함수 처리만 추가합니다. 기존 주문·금액·재고·접수 영수증을 변경하지 않습니다. `supabase/tests/pickup.mjs`는 독립 메모리 DB에서 검증합니다.

### 공통 푸터와 이용 안내

메인·TMI·관리자·이용 안내 페이지는 같은 판매자 정보와 `site-footer.css`를 사용합니다. 푸터의 상호·대표자·사업자등록번호·통신판매업 신고번호·주소·고객 문의·개인정보 보호책임자는 운영자가 제공한 정보입니다. 공정위 사업자 확인은 숫자만 넣은 등록번호로 연결하며, 외부 공개 정보의 조회 성공이나 사업자 상태를 보증하는 표시는 하지 않습니다.

`policies.html#terms`는 상품 구매 약관, `policies.html#privacy`는 개인정보처리방침입니다. 우체국택배 위탁과 실제 Supabase 리전(Singapore, ap-southeast-1), 브라우저 주문자 정보 저장을 명시했습니다. 주문 화면의 기존 동의 설정을 유지하면서 방침 상세 링크를 추가했습니다. 일반 페이지와 정책 페이지 모두 GitHub Pages의 `/farmer/` 경로와 Sites 루트에서 같은 상대 링크로 열립니다.

법정 보존기간 이후의 파기·분리 보관은 운영자가 관리해야 합니다. 이번 변경으로 자동 파기 기능을 추가한 것은 아닙니다. 택배사·저장 위치·연락처·처리 목적 등이 바뀌면 방침과 공통 푸터도 함께 수정하세요.

### 선물 구매와 주소 등록 링크

- `/#gift`: 주문 영역의 선물하기 탭. 주문자·표시 이름, 받는 분 호칭, 상품·상자 수, 메시지를 입력하고 서버에서 금액과 할인코드를 검증한 뒤 구매 신청을 저장합니다. 링크는 각 받는 분마다 한 개씩 생성합니다.
- `/#receive&gift=…`: 비공개 전용 링크로 접속해 수령자 본인의 이름·연락처·우편번호·주소를 등록합니다. 메시지와 “OOO님께서 OOO를 선물하셨습니다”를 표시하며 구매 금액·구매자 연락처·기등록 주소는 공개하지 않습니다. 공유 링크는 공개 운영 주소 `https://yoongahee.com/farmer/#receive&gift=…`을 사용합니다. 링크 토큰을 URL fragment에 넣고 no-referrer를 사용합니다. 로그인·결제는 요구하지 않습니다.
- 관리자 ‘선물 링크 관리’: 구매 선물의 입금 확인, 링크 복사, 무상 선물 링크 생성, 주소 등록 상태, 기한 연장·취소. 기존 ‘선물 주문 등록’은 배송지를 알고 있을 때 직접 등록하는 기능으로 유지합니다.
- 선물 구매는 기존 `farmer_orders`의 유상 주문, 관리자 무상 링크는 기존 무상 선물 주문으로 저장합니다. 손익분석에 중복 수입이 생기지 않습니다. 유상 선물은 입금 확인 시, 무상 선물은 링크 생성 시 판매 가능 재고를 차감해 확보합니다. 배송지 등록 시에는 다시 차감하지 않습니다. 주소 등록 전 발송·배송 완료는 서버에서도 차단합니다.
- 주소 등록 기한은 유상 선물의 입금 확인 시점부터 기본 30일, 관리자 무상 선물은 1~90일 설정 가능합니다. 기한 만료만으로 취소·재고 복구·환불이 자동 실행되지 않습니다. 관리자가 연장하거나 취소하며, 취소 시 기존 재고 복구 로직을 사용합니다. 은행 환불은 판매자가 별도로 처리해야 합니다.
- 256비트 무작위 토큰과 링크는 `farmer_private.gift_links`에서 관리하며 테이블 직접 조회는 차단합니다. 공개 RPC는 토큰으로 선물의 공개 메시지와 최소 상태만 반환하고, 주소 등록은 최초 한 번만 허용합니다. 같은 요청의 재시도는 중복 주문·중복 차감을 만들지 않습니다.
- 선물 링크는 구매자/관리자가 직접 복사해 전달합니다. 카카오톡·문자 자동 발송이나 자동 입금 확인은 연결하지 않았습니다. 구매 신청 결과는 같은 탭의 세션 저장소에 보관하고, 링크는 구매한 브라우저의 로컬 저장소에 최대 90일간 보관합니다. 보낸 선물 확인하기에서 다시 조회할 수 있으며, 브라우저 데이터를 삭제한 경우 관리자에게 문의하세요.
- `supabase/tests/gift-links.mjs`에서 권한, 가격 위조, 토큰, 개인정보 반환 범위, 유상·무상 수입 구분, 재고, 재시도, 주소 등록 전 발송 차단, 기한 만료·연장·취소를 확인합니다.

선물 구매의 확인·신청·입금 안내는 팝업 없이 페이지 안에 표시합니다. 구매 동의는 기본 체크이며 변경할 수 있습니다. 구매자는 서버가 입금을 확인한 선물에만 링크 입력칸과 복사 버튼을 표시합니다. 관리자의 선물 링크 관리에서는 입금 대기·기한 만료·취소 상태를 포함한 모든 링크를 확인·복사할 수 있으며, 받는 분의 배송지 등록 가능 여부는 기존 서버 상태에 따릅니다. 입금 안내에는 평일 기준 1일 소요 문구를 표시하며, 새로고침 버튼·탭 복귀·화면이 열린 동안의 주기적 조회로 상태를 갱신합니다. 조회 실패 시에도 미확인 링크는 표시하지 않습니다. 공유 URL은 로컬 미리보기에서도 공개 운영 주소를 사용합니다.

### 통합 주문 탭과 보낸 선물 조회
- 주문 영역은 `주문하기 / 주문서 확인하기 / 선물하기 / 보낸 선물 확인하기 / 선물받기` 다섯 탭입니다. `#order`, `#order-lookup`, `#gift`, `#sent-gifts`, `#receive&gift=…`로 직접 열 수 있습니다. 키보드 좌우·Home·End와 브라우저 뒤로 가기를 지원합니다.
- 기존 `gift.html`, `gift-receive.html#gift=…`는 같은 페이지의 해당 탭으로 연결되므로 기존에 보낸 링크도 계속 사용할 수 있습니다.
- `farmer_lookup_gifts`는 이름·연락처의 정확한 일치로 구매 내역을 20건씩 조회합니다. 기존 주문 조회와 전화번호별 조회 제한을 공유합니다. 개인정보와 메시지, 링크 토큰은 반환하지 않습니다.
- 선물 구매 브라우저에는 주문번호와 링크 토큰만 최대 90일간 로컬 저장소에 보관하며, 여러 번 구매한 내역을 누적합니다. 조회 내역과 로컬 보관 정보를 연결해 서버에서 입금 상태를 확인한 후에만 링크를 표시합니다. 다른 기기에서도 구매 내역은 조회되지만 링크 복사는 구매 브라우저에서 하거나 판매자에게 문의해야 합니다. 브라우저 저장이 차단돼도 현재 탭의 구매 신청 결과와 선물받기는 이용할 수 있습니다.
- 링크 복사 직전에도 상태를 재확인합니다. 받는 분의 배송 주소·연락처는 구매 내역 조회나 선물 링크에 표시하지 않습니다.

관리자 주문 현황의 네 상태 카드에는 전체 주문 기준 건수와 kg 합계가 함께 표시됩니다. 주문에 저장된 총 중량을 더하며, 무상 선물·방문 수령도 각 상태에 포함하고 취소 주문은 제외합니다. 체크한 주문의 합계 중량도 선택 건수 옆에 표시합니다.

입금 계좌 안내와 복사 버튼은 주문하기·선물하기의 왼쪽 안내, 모든 페이지의 공통 푸터, 주문/보낸 선물 조회의 입금 대기 카드에 표시합니다. 전액 할인된 0원 주문과 입금 확인 이후의 조회 카드에는 입금 계좌를 표시하지 않습니다. `payment-config.js`가 공통 설정이며, 복사되는 내용은 `국민 697201-00-081099`입니다.

### 관리자 배송 정보 수정
- 주문 상세의 ‘배송 정보 수정’에서 받는 분·연락처·우편번호·주소·상세주소·배송 메모·택배사·송장을 변경합니다. 주소 검색과 직접 입력을 지원합니다. 방문 수령은 받는 분과 수령 메모만 수정하며 장소·상품·수량·금액은 유지합니다.
- `farmer_admin_update_delivery`는 인증된 허용 관리자만 실행할 수 있습니다. 서버가 입력을 검증하고 주문 버전을 확인하며, 동일 요청의 재시도는 한 번만 반영합니다. 재고·결제 금액·주문 단계는 변경하지 않습니다. 비공개 변경 이력에는 관리자·주문·변경 필드명·버전과 요청 해시만 남기고 주소 사본은 저장하지 않습니다.
- 아직 주소를 등록하지 않은 선물은 입금 확인 후 관리자가 대신 등록할 수 있습니다. 이때 주소 등록 완료로 처리해 받는 분의 추가 등록을 막고 발송을 준비할 수 있게 합니다. 이미 발송된 주문을 수정해도 실제 택배사의 배송지는 자동으로 바뀌지 않습니다.
- 수정 초안은 브라우저 저장소에 저장하지 않으며 닫기·로그아웃 시 지웁니다. 연결 문제로 결과가 불확실할 때는 같은 요청으로 다시 확인합니다.

### 주문 삭제 보관함과 엑셀 다운로드

- 관리자 주문 상세의 `주문 삭제` 또는 체크 후 `선택 주문 삭제`를 사용합니다. 완전 삭제하지 않고 기본 목록·고객 조회·선물 링크 관리에서 제외합니다. `주문 상태 → 삭제된 주문`에서 조회·복원할 수 있습니다.
- 입금 대기·배송 준비·취소 주문만 삭제할 수 있습니다. 삭제 시 아직 살아 있는 주문을 취소하고 확보했던 재고만 한 번 복원합니다. 주문·재고·할인 이력은 보존합니다. 입금 환불은 별도 처리이며, 복원은 취소 상태로만 돌아옵니다. 이미 배송·수령이 시작되거나 완료된 주문은 삭제를 차단합니다.
- `엑셀 다운로드`는 검색·상태·주문 구분 조건에 맞는 전체 주문을 `.xlsx`로 내려받습니다. 페이지에 보이는 50건 제한과 무관하며 10,000건 초과 시 검색 조건을 좁히도록 안내합니다. 전화번호·우편번호·송장은 문자열로, 금액·수량은 숫자로 저장합니다. 셀 내용은 수식으로 실행되지 않습니다.
- 내보내기는 허용된 관리자만 가능하며, 파일에는 주문자·받는 분의 연락처와 주소가 포함됩니다. 선물 링크 토큰은 포함되지 않습니다. 받은 파일은 안전하게 보관해 주세요.

### 윤가희·홍세환의 무상 선물 집계

- 관리자 `선물 주문 등록`에서 선물하는 사람(윤가희·홍세환·윤가희&홍세환)을 선택합니다. 공동 선물은 별도 항목으로 집계하며 개인별 수량에 중복 합산하지 않습니다. 선택은 요청에 포함되어 재시도해도 같은 사람·주문·재고로 처리됩니다. 기존 발신자 정보가 없는 무상 선물은 임의로 추정하지 않고 `미지정`으로 집계합니다.
- `고구맙습니다홍세환선물용`, `고구맙습니다윤가희선물용` 두 코드의 **상품 한 개 가격이 전액 할인된 수량**을 각각 집계합니다. 예: 5kg 두 상자 44,000원에서 22,000원 할인이라면 무상 선물은 한 상자입니다. 일반 구매자의 유료 선물하기나 다른 할인코드는 이 집계에 포함하지 않습니다.
- 가격 시뮬레이션 `선물용 5kg`에 등록된 무상 선물 수량과 사람별 수량을 자동 표시합니다. 접수 대기 포함, 취소·삭제 제외이며 선택한 연도의 한국시간 등록일을 기준으로 계산합니다. 배송 단계 변경·선물 주소 등록은 추가 수량으로 세지 않습니다.
- 자동 집계된 기존 선물과 수동 `추가 선물 계획`을 구분합니다. 기존 선물의 재고는 시뮬레이션에서 다시 차감하지 않습니다. 기존 주문의 미기록 택배비·포장비는 공통 기본 단가로 추정해 장부 지출에 보충하며, 추가 계획 비용과 구분합니다. 시뮬레이션 탭을 열거나 새로고침하면 최신 수량을 불러옵니다.

### 무상 선물 방문 수령

관리자 선물 등록에서도 `호풍미 5kg 방문 수령`을 선택할 수 있습니다. 받는 분 성함·연락처·수령 메모를 입력하며 배송 주소는 요구하지 않습니다. 서버가 수령 장소를 `원북면 원이로 804-59 / 홍세환 소셜라운지`로 고정합니다. 상품·배송비 모두 0원이며 등록 시 재고를 확보합니다. 방문 수령도 사람별 5kg 무상 선물 집계에 포함되고, 택배 선물과 같은 등록에 섞어서 접수할 수 있습니다.

### 방문 수령 선물 비용

가격 시뮬레이션의 추가 선물 계획은 택배와 방문 수령 수량을 별도로 입력합니다. 택배비는 판매·택배 선물 수량에만, 상자비는 방문 수령 선물을 포함한 모든 추가 수량에 적용합니다. 두 선물 모두 판매액은 0원이며 5kg씩 재고 계획에 반영합니다. 자동 집계된 등록 선물에도 택배/방문 구분을 표시하며, 기존 내역을 추가 계획에 중복 합산하지 않습니다.

## 택배비·상자비 기본값과 기존 주문 비용

손익분석의 ‘택배비·상자비 자동 계산’에서 공통 기본 단가를 저장합니다. 최초 값은 택배비 4,000원, 상자비 1,500원이며 관리자만 변경할 수 있습니다. 다른 기기에서도 같은 값을 불러옵니다.

- 선택한 연도의 입금 확인·배송 중·배송 완료 주문을 상자 수량으로 집계합니다. 유상·무상 선물도 포함하며, 방문 수령은 상자비만 계산합니다. 입금 대기·취소·삭제는 제외합니다.
- 연도는 수입과 동일하게 한국시간 입금 확인일(없으면 주문일)을 기준으로 합니다.
- 실제 장부를 자동 생성하지 않습니다. 총지출·예상 손익에는 미기록 비용 추정을 포함하고, 월별 장부 그래프·내역은 실제 기록만 표시합니다.
- 실제 비용을 기록할 때는 분류를 `배송비` 또는 `포장비`로 지정합니다. 해당 연도에 기록한 금액을 각각 단가 기준 추정액에서 빼고, 부족한 부분만 추정 비용으로 더합니다. 기록액이 추정액보다 크면 실제 기록액을 유지합니다.
- 가격 시뮬레이션은 같은 기본값과 기존 주문 비용 추정을 불러온 뒤 추가 판매·선물 비용을 더합니다. 시뮬레이터 안에서 단가를 바꾸면 기존 주문의 추정 비용도 함께 재계산하지만, 공통 기본값은 변경하지 않습니다. 기존 선물의 재고는 다시 차감하지 않습니다.

## 상자별 송장과 엑셀

수량이 4인 주문은 주문·결제·재고는 한 건으로 유지하고, 송장번호는 상자 1~4 각각에 입력합니다. 개별 발송, 배송 정보 수정, 선택 주문 일괄 발송에서 같은 상자별 입력을 사용합니다. 기존 단일 송장번호는 첫 번째 상자에 보존하며, 나머지 상자는 미입력으로 표시합니다. 송장 미입력은 허용하지만 동일 주문 내 중복된 번호나 상자 수를 넘는 번호는 저장할 수 없습니다. 택배사는 주문 단위로 동일하게 사용하며 배송 상태도 주문 단위로 관리합니다. 방문 수령은 송장을 입력하지 않습니다.

엑셀 다운로드는 상품 수량만큼 행을 만들고 각 행 수량을 1로 표시합니다. ‘주문 전체 수량’과 ‘상자 순번’으로 원래 주문을 식별하고, 연락처·주소와 해당 상자 송장번호를 함께 내보냅니다. 상품 금액·할인·배송비를 상자별로 나눠 합계가 원래 주문과 정확히 일치하도록 1원 단위 나머지를 순서대로 배분합니다. 원래 수량 필드는 참고용이므로 합산에는 ‘수량’을 사용합니다. 한 번에 30,000상자까지 내보내며 초과하면 검색 조건을 좁히도록 안내합니다.


## 후기 게시판

홈페이지의 주문 영역 아래, 푸터 바로 위에 짧은 후기와 최대 3장의 사진을 남기는 공간을 추가했습니다. 이름·연락처·주문 확인은 요구하지 않습니다. 닉네임을 비우면 서버에서 `고구맙습니다 구매자`로 저장합니다. 후기 글은 1~1,200자이며 공개 동의 후 등록합니다.

- `reviews.js` / `reviews.css`: 작성, 사진 미리보기·삭제·압축, 카드 목록과 사진 확대. 원본은 최대 20MB이며 JPEG로 재인코딩해 촬영 정보를 제거하고 긴 변 1,600px, 저장 크기 최대 1.5MB로 제한합니다.
- `20261024042108_customer_reviews.sql`: 주문과 분리된 비공개 테이블과 Storage 버킷. 서버에서도 사진 3장과 업로드 경로·유효 시간·업로드 완료를 검사합니다. 공개된 후기 사진만 읽을 수 있고 숨기면 사진 접근도 차단합니다.
- 관리자 ‘후기 관리’: 공개/숨김 필터, 숨기기·다시 공개. 변경 버전을 확인해 다른 화면의 수정을 덮어쓰지 않습니다.
- 익명 작성 요청 제한과 재시도 처리가 있으며, 글은 HTML로 실행하지 않습니다. 주문·재고·결제 데이터는 변경하지 않습니다.

**연결 확인:** 후기 마이그레이션을 thanks-goguma 프로젝트에 적용했습니다. 실제 Storage API에서 비공개 초안의 JPEG 3장 업로드(각 200 응답), 4번째 사진 차단, 게시 전 이미지 읽기 차단과 누락 사진 게시 차단을 확인했습니다. 공개 확인용 후기는 등록하지 않았습니다. 로컬 데이터베이스 회귀 테스트와 브라우저 모의 검증도 통과했습니다.
